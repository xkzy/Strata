# Deterministic LLM Logic Verification Runtime

Strata implements a built-in **Deterministic LLM Logic Verification Runtime** designed to verify mathematical calculations, logical deductions, variable bounds, SI dimensional units, and structured schemas generated by the LLM **without using another LLM as a judge or verifier**.

## Fundamental Design Principle

> **The LLM generates hypotheses, claims, calculations, plans, or structured results. Deterministic engines verify what can actually be verified.**

```text
       LLM Output (Hypothesis / Claim / Plan)
                       ↓
            Claim Extraction / Parsing
                       ↓
           Structured Verification IR
                       ↓
          Deterministic Verification Planner
       ┌───────────┬────────────┬────────────┐
       │   CAS     │    Rule    │ Constraint │
       │ Mathics3  │   Engine   │   Engine   │
       └─────┬─────┴─────┬──────┴─────┬──────┘
             └───────────┼────────────┘
                         ↓
               Deterministic Result
             [ PASS / FAIL / UNKNOWN ]
                         ↓
             Virtual Context Audit Record
                         ↓
          Compact Observation to Agent / LLM
```

---

## 1. Tri-State Verification Model

Verification is strictly tri-state:

* **`PASS`**: Deterministic formal evidence confirms the claim.
* **`FAIL`**: Deterministic formal evidence contradicts the claim.
* **`UNKNOWN`**: The verifier cannot establish correctness (e.g., natural language reasoning with no formal semantics).

> **Core Correctness Invariant:** `UNKNOWN` is **NEVER** converted into `PASS`. No probabilistic guessing or false positives are permitted.

For composite multi-claim expressions, a composite status of **`PARTIAL`** is provided if some components pass while others fail or remain unknown.

---

## 2. Verification Engines & Routing

The Deterministic Planner routes claims hierarchically to the cheapest authoritative engine:

| Claim Type | Authoritative Engine | Capabilities & Invariants |
| :--- | :--- | :--- |
| **`arithmetic`** | Fast Numeric & Exact Rational Evaluator | Exact rational fractions (`1/3 + 1/6 == 1/2`), large integers, float tolerance checks. |
| **`symbolic`** / **`equation`** | Mathics3-Core CAS | Symbolic integration, differentiation, polynomial factorization, limits, matrix operations. |
| **`proposition`** | Propositional Rule Engine | Recursive-descent AST parser, truth-table model checker, Modus Ponens validation, countermodel discovery, contradiction detection. |
| **`constraint`** | 1D Interval Constraint Solver | Single & multidimensional interval bounds (`[min, max]`, `>`, `>=`, `<`, `<=`, `!=`), bound intersection, and empty feasible region conflict detection. |
| **`unit_dimension`** | SI Dimensional Analysis Engine | 7 SI base dimensions `[L, M, T, I, Θ, N, J]`, derived units (`N`, `J`, `W`, `Pa`, `Hz`), prefix scaling, and dimensional homogeneity validation. |
| **`schema_type`** | JSON Schema & Syntax Validator | Syntactic integrity, required keys, type enforcement (`string`, `number`, `boolean`, `array`, `object`). |
| **`composite`** | Composite Aggregator | Evaluates multi-claim sets, returning `PASS`, `FAIL`, `PARTIAL`, or `UNKNOWN`. |

---

## 3. SI Dimensional Analysis

The unit verifier decomposes all physical units into exponents of the 7 base SI dimensions:

$$\text{dim}(Q) = L^a \cdot M^b \cdot T^c \cdot I^d \cdot \Theta^e \cdot N^f \cdot J^g$$

Before numerical conversion is performed, dimensions must match exactly:
* $50\ \text{m/s}$ vs $50\ \text{kg} \rightarrow$ **`FAIL`** (`[L T^-1] != [M]`).
* $1000\ \text{m}$ vs $1\ \text{km} \rightarrow$ **`PASS`** (`[L^1] == [L^1]`, $1000\ \text{m} = 1000\ \text{m}$).

---

## 4. External State & Virtual Context Integration

To prevent context window bloat:
1. **Full Verification Audit Trail** (execution timestamps, variable assignments, countermodels, canonical hashes) is stored in the **Virtual Context Store**.
2. **Compact Observation** (e.g. `Verification: PASS | 2384 * 7291 = 17381744`) is injected back to the model context.

---

## 5. API Endpoints

### 1. Verify Structured Claim
`POST /v1/strata/verify`
```json
{
  "claim_id": "claim_01",
  "type": "proposition",
  "premises": [
    "A -> B",
    "A"
  ],
  "claimed_value": "B"
}
```
**Response:**
```json
{
  "claim_id": "claim_01",
  "status": "PASS",
  "type": "proposition",
  "backend_used": "deterministic_rule_engine",
  "evidence": "Logical deduction formally proven across all 4 truth valuations.",
  "compact_observation": "Verification: PASS | Deduction formally proven",
  "execution_time_ms": 0.12,
  "cache_hit": false
}
```

### 2. Extract & Verify Text Claims
`POST /v1/strata/verify/claims`
```json
{
  "text": "The result is 2384 * 7291 = 17381744. Given x > 0 and x < 10, x = 5."
}
```
**Response:**
```json
{
  "claim_count": 2,
  "results": [
    {
      "claim_id": "claim_arith_1",
      "status": "PASS",
      "type": "arithmetic",
      "compact_observation": "Verification: PASS | 2384 * 7291 = 17381744"
    },
    {
      "claim_id": "claim_constr_1",
      "status": "PASS",
      "type": "constraint",
      "compact_observation": "Verification: PASS | x = 5 in bounds"
    }
  ],
  "compact_observation": "Verification: PASS | 2384 * 7291 = 17381744\nVerification: PASS | x = 5 in bounds"
}
```

`GET /v1/strata/verify/metrics`
